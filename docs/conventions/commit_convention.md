# Git 커밋 컨벤션

## 1. 커밋 메시지 구조

커밋 메시지는 아래 세 번으로 구성합니다:

```
<type>: <Subject>

<body>

<footer>
```

* **type**: 커밋 목적을 나타내는 태그 (`feat`, `fix`, `docs` 등)
* **Subject**: 메시지 제목 (50자 이벤, 말지표·특수문자 없음)
* **body** (선택): 변경 **무엇**과 **왜**에 대해 설명 (72자/행)
* **footer** (선택): 이슈 ID 등 (`Fixes: #123`, `Related to: #45`)

---

## 2. Type (커밋 타입)

| 타입         | 설명                            |
| ---------- | ----------------------------- |
| `feat`     | 새로운 기능 추가                     |
| `fix`      | 버그 수정                         |
| `docs`     | 문서 수정                         |
| `style`    | 코드 폼맷, 세미콬론 등 수정 - 시스템적 변경 없음 |
| `refactor` | 리파터리드 (기능 변화 없음)              |
| `test`     | 테스트 추가/수정                     |
| `chore`    | 빌드, 패키지 관리 기타 변경              |

---

## 3. Subject (제목)

* 50자 이내
* 마침표, 특수문자 사용하지 않음
* 간단한 문장으로 입력
* 영문으로 표기하는 경우 동사를 가장 앞에 두고 첫 글자는 대문자로 표기, 과거 시제 사용 안함

---

## 4. Body (본문)

* 한줄에 72자 이내
* 분량 상관 없이 상세히 작성
* **무엇**을 변경했는지, **왜** 변경했는지에 중점

---

## 5. Footer (바닥글)

* 선택 사항
* 이슈 ID 포함 (`Fixes: #45`, `Ref: #456`, `Related to: #78, #90`)

---

## 6. 커밋 예시

```text
feat: 회원 탈퇴 기능 추가

사용자가 계정을 삭제할 수 있도록 API 기능을 구현했습니다.

Resolves: #130
Ref: #122
Related to: #101, #87
```
