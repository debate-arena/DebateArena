### 기획 구체화

### 온라인 실시간 토론 플랫폼

**기획 목적**: 사용자가 실시간으로 논쟁하며 설득력을 겨루는 플랫폼  
**주요 프로세스**:

1. 유저 랜덤 매칭  
2. 유저 채팅방 입장  
3. A팀 주장 및 근거 제시  
4. B팀 주장 및 근거 제시  
5. A팀이 B팀에게 질문  
6. B팀이 A팀에게 답변  
7. B팀이 A팀에게 질문  
8. A팀이 B팀에게 답변  
9. 최종 판결 (투표 or 판사 역할 참여자)

---

### 온라인 모의 재판 플랫폼

**기획 목적**: 실제 형사재판 절차를 기반으로 한 시뮬레이션 교육용 플랫폼  
**주요 프로세스**:

1. **개정 선언**  
2. **검사 측 서론 발표**  
   - 사건 개요 및 유죄 주장 개진
3. **변호 측 서론 발표**  
   - 피고인의 무죄/감형 주장 설명
4. **검사 측 논리 정리 발표**  
   - 증거와 진술을 종합하여 법적 근거 기반 유죄 논리 제시
5. **변호인 측 논리 반박 발표**  
   - 검사 논리에 대한 법률적 반박 및 대안 해석 제시
6. **판사 판결 선고 및 이유 설명**  
   - 결론 도출과 함께 교육적 관점에서의 해설 포함

## 2. 기술 구성 설계

### Redis: 실시간 상태 및 세션 관리

| 기능 | 적용 위치/모듈 | 상세 역할 |
| --- | --- | --- |
| 방 정보 관리 | 방 관리 서비스 (Room Service) | 방 생성, 입장, 퇴장 시 실시간 상태 업데이트 |
| 참가자 정보 | 참가자 세션 관리 모듈 | 현재 입장한 참가자 리스트 실시간 저장 및 조회 |
| 발표 순서 관리 | 발표 진행 컨트롤러 | 발표자 순서 및 타이머 상태 저장 |
| 투표 현황 실시간 캐싱 | 투표 서비스 | 실시간 투표 집계, 결과 즉시 반영 및 조회 |

---

### Backend Server

| 기능 | 적용 위치/모듈 | 상세 역할 |
| --- | --- | --- |
| Kurento 기반 WebRTC 미디어 중계 | 미디어 서버 | AI 서버로 미디어 데이터 중계 및 나머지 클라이언트에게 전송 |
| 실시간 미디어 데이터 수신 | AI 서버 | 미디어 데이터 수신 후 STT 및 판정 수행 |
| AI 서버로부터 판단 데이터 및 STT 데이터 수신 | 메인 서버 | AI 분석 결과 수신 및 데이터 저장 |
| 데이터 저장 | 메인 서버 | RDB 및 NoSQL(MongoDB)에 결과 저장 |

---

### RDB (MySQL/PostgreSQL): 정형 데이터 저장

| 기능 | 적용 위치/모듈 | 상세 역할 |
| --- | --- | --- |
| 승패 저장 | 메인 서버 | 토론 승패, 점수, 평가 결과 등 정형 데이터 저장 |

---

### MongoDB: 비정형 및 대용량 데이터 저장

| 기능 | 적용 위치/모듈 | 상세 역할 |
| --- | --- | --- |
| 발언 로그 저장 | 발언 기록 서비스 | 각 발언의 텍스트, 시간, 사용자 정보 등 JSON 형태 저장 |
| AI 상세 분석 결과 | AI 분석 서비스 | 감정 분석, 논리 평가 등 JSON 형태로 저장 |
